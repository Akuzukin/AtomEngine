# 《碎星哨站》引擎问题与组件缺口

## 粒子随机区间（2026-10-15）

粒子组件和 `.particle` 新增可选的生命周期、初始速度、起止尺寸以及起止 RGBA 颜色区间。GPU 在出生时按不同随机序列采样并保存个体端点，之后按自身生命周期插值，避免逐帧随机闪烁。编辑器首次启用时基于固定参数生成小范围默认区间，旧资产默认关闭随机，区间上下界与非有限数值在加载和保存时校验。

原生 GPU 回读验证64个粒子的12个采样通道均在范围内且存在分布差异；随机参数序列化、倒置区间拒绝、旧资产默认关闭及完整工作流回归通过。运行记录见 generated/particle-assets-editor/logs/AtomEngine.log。

## 独立粒子资产（2026-10-15）

编辑器支持新建、双击编辑、保存和另存为 `.particle`；资产在独立 World 中预览，保存前验证并原子替换。场景组件可导出资产、拖拽绑定资产；脚本组件字段可拖入资产并创建原生组件。发行收集器解析 `.particle` 内的纹理引用。回归覆盖中文文件名、重名创建、参数往返、非法保存保留原文件、资产编辑不修改场景与原生实例化。

回归还捕获了 SceneRuntime 音频参数每帧 JSON 签名序列化路径的访问异常，调用栈记录于 generated/particle-assets-debug-detail.log；该路径已改为类型化参数快照比较，避免每帧序列化。

修复后普通运行配置连续两次通过完整原生回归。发行回归确认 `.particle` 与其纹理进入加密包并实际加载，脚本 Reference 与启动器已同步。最新版编辑器位于 generated/particle-assets-editor，使用 Tools/Open-Editor.ps1 自动选择。

## GPU 粒子系统与编辑器重写（2026-10-15）

## 文档口径冲突与实施决定

- 文档同时指定网页单文件和3D引擎。用户明确要求使用这个引擎，因此主交付为AtomEngine Windows x64原生游戏与可编辑 `.atproj`；没有把网页Demo冒充原生游戏。
- 采用60Hz固定战斗更新，最多累积0.25秒，渲染独立。升级与暂停精确冻结战斗，保留步长余量。文档“动态时间步/240Hz”与“固定60Hz”不一致，以性能预算的60Hz为准。
- 2400×1600设计像素映射到24×16世界单位，玩家半径0.22、磁吸1.2、移动3.2世界单位/秒。
- 稀有度作为候选品质与统计标签；伤害成长取实际武器/被动效果，不额外乘隐藏稀有度倍率。
- 金币以整数十分之一记账，避免0.1金币累计误差。星辰来自精英/Boss；死亡和放弃只入账已经拾取的资源。
- 2026-10-15移除命中暂停50ms/击杀慢镜120ms对全局战斗步长的影响。标准胜利以战斗计时1200秒为准，明确暂停和升级界面仍冻结战斗。

## 编辑器放大视口UI仍使用旧尺寸（2026-10-15）

上一轮尺寸诊断覆盖独立游戏，漏掉编辑器视口路径。实际发现普通Viewport将uiRenderSize设为3D场景缓冲而不是UI合成缓冲；DrawPlay没有同步uiViewportSize/uiRenderSize。窗口放大后布局仍围绕较小的场景缓冲居中，页脚和右侧锚点也无法到达屏幕边缘。

修复：普通/放大视口统一使用gOverlayBuffer尺寸，OverlayPass绘制前再次同步实际目标尺寸；预览图比例匹配实际合成图，UI输入映射到合成缓冲像素，3D拾取保留独立场景坐标。原生工作流新增实际缓冲尺寸断言，覆盖窗口调整、全屏/恢复、普通/放大视口与重复Play。源码和新版编辑器位于generated/components-editor；正在运行的旧实例需要重新打开。

## 底层Overlay资源被3D重建覆盖（2026-10-15）

实际根因：BufferManager::InitializeBuffers重建3D渲染分辨率时，同时以3D宽高创建主Overlay；CompositePS却用SV_Position的窗口像素坐标直接读取Overlay。其宽高与交换链不同，会裁切/错位，CPU uiRenderSize同步并不能证明最终像素正确。

修复：主视图Overlay分配始终使用交换链宽高，离屏视图Overlay仍使用自己的目标尺寸；窗口重建明确操作主视图资源。Present校验实际Overlay与交换链目标一致；SpriteRenderer投影也使用当前Overlay尺寸。原生测试主动在窗口调整期间切换720p/1080p，修复前退出1并报Primary Overlay dimensions differ from final composite target，修复后退出0。

新增GPU验收：在ImGui合成前回读最终合成图，检查右下角锚点绿色块的真实像素，覆盖第10/16/27/42帧。四次均通过；截图位于generated/outputs/x64/Release/Smoke/overlay-composite-*.raw，PNG示例位于generated/components-editor/Smoke。默认编辑器目录已重新构建并通过同一像素回归，不再只更新独立目录。

## 第一次命中后玩法停止（2026-10-15）

使用当前实际Outpost.scene的副本复现：首次子弹命中时，EffectSpawner调用Particles.Emit抛出Object has no particle emitter，经Simulation.Hit/ProjectileController/OutpostRuntime.OnUpdate传播，引擎将主玩法脚本标记failed。编辑器仍运行但战斗时钟停止，表现为约两秒卡死，并非已证实的GPU死锁。

实际场景中的BurstEmitter0～3对象存在，却没有ParticleEmitter组件。此前绑定仅检查对象非null，导致把缺失组件的对象当作有效GPU发射器。已在不重写其他场景设置的前提下恢复四个组件；绑定现在检查实际组件。特效回调返回成功/失败，缺失、失活或原生效果调用失败时使用现有几何特效池；单个失败发射器停用后不会反复抛错，也不会中断伤害/击杀结算。

验证：22项规则回归通过，新增GPU效果不可用仍连续命中/击杀，以及成功GPU效果不重复生成mesh。保留缺失组件的FreezeCheck场景修复前退出1，修复后3000帧退出0：nativeEmitters=0，Elapsed=12.70秒，击杀3。恢复组件的FreezeGpuCheck同样3000帧退出0：nativeEmitters=4，Elapsed=12.72秒，击杀18。两份原生报告在Build/FreezeCheck和Build/FreezeGpuCheck/Diagnostics/runtime-check.json；诊断禁用存档写入。默认及独立编辑器游戏脚本、正式发行包已更新。
